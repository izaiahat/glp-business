## Stage lease contract

- Fixed private runtime path: `reports/glp-clinic-scout/affiliate-machine/applications/.maxbounty-capacity-lease.json` beneath `BUSINESS`. No runtime lease is committed or installed.
- Start: `with capacity_lease_stage() as token:` creates a random 256-bit owner token and active expiry. Retain the token privately for the next interpreter; do not put it in reports, command-line arguments, URLs, browser state or portal requests. It is a local custody capability, not a login credential.
- Resume: `with capacity_lease_stage(owner_token=token):` requires the existing active, unexpired lease and matching token. Every stage verifies and renews on entry and normal exit. Missing, malformed, released, expired or wrong-owner leases refuse before the stage body. A missing file permits only a new start, never a resume.
- Final: `with capacity_lease_stage(owner_token=token, final=True):` verifies/renews normally, then writes a released tombstone after successful cleanup. It does not unlink the lease or guard locks. Release permits a new start with a new token; the previous token cannot resume. Exceptions/crashes retain the active reservation until expiry. The single-process factory uses a final stage and closes its owned browser before releasing custody.
- Expiry: default 300 seconds; explicit finite positive TTL must be at most 900 seconds. UTC epoch timestamps use the trusted host wall clock. An observed clock regression refuses. There is no heartbeat, daemon or automatic recovery. A stage overrun cannot renew/release an expired lease; stop rather than reset identity or budgets. Admission does not authorize effects beyond expiry.
- Takeover: only a **new** start after expiry can replace an active reservation, and only after obtaining both original kernel locks. Even an expired lease cannot be taken over while another stage still holds those locks. The new owner, former-owner SHA-256 references, old expiry and takeover timestamp are persisted together in the atomic replacement. Takeover history survives release and later starts. A stale former owner cannot renew or release the successor.
- Serialization: the original `.application-machine.lock` and MaxBounty `owner.lock` are acquired nonblocking in the original order and held throughout each stage. They are never replaced/unlinked. **Never flock the lease JSON itself:** it is replaced atomically, so its inode is not a valid mutex. Lease writes use the existing same-directory temp file, mode 0600, file fsync, rename and directory fsync. Nonregular/symlinked or malformed lease files refuse; they are not automatically repaired.

The original profile-idle check runs on every stage. Browser/heavy admission remains a separate prerequisite. The durable token fences **cooperating capacity callers**; it cannot keep a kernel flock alive after interpreter exit or fence unrelated legacy writers that ignore the lease. Adoption must keep such writers excluded across the vault interval and review clock/expiry policy. Expiry is not permission to manipulate another browser or retry an uncertain effect.

## Resumable controller contract

`fresh_browser_stage(pins=…, cdp=…, drain_events=…, switch_tab=…, owner_token=…, final=…)` yields `(token, producer)` inside the existing lease/lock scope. Only the external browser daemon, its owned context and its paused event queue survive; no Python object is assumed to survive `browser_exec`.

- **Prepare:** omit `owner_token` for a new run. The real `begin()` still requires an exclusive blank browser and installs interception before navigation. On a normal exit the owned context remains alive and the controller is checkpointed. The next stage supplies the returned token through the private local custody handoff, never a report or portal request.
- **Vault/MFA interval:** the authorized agent invokes the actual origin-bound vault/MFA tools outside this Python module, on the exact owned tab in the same named browser session. Passwords, cookies and codes never enter this API. Re-import the module for each subsequent stage; enter with the token and call `producer.poll()` to drain paused authentication requests/responses. A poll without a response is not authentication success. Request and response pauses may be handled in different interpreters.
- **Resume:** verify source pins, the active owner/expiry and checkpoint hash before any browser access; restore only allowlisted fields. Recheck exact target/context/session/main-frame identity against the browser. Never rerun `begin()`, reinstall Fetch, recreate a context, navigate back to login or infer authentication from the configured account. Session loss or binding changes refuse.
- **Final:** enter with `final=True`, then use `run_once(..., read_queue, producer.probe)`. One final stage contains the entire campaign dispatch and response; partially completed campaign work is deliberately **not resumable**. A successful final exit closes the owned context, records a closed tombstone and releases the lease. Missing capacity markers remain UNKNOWN. A second final call cannot reuse the released owner.

The checkpoint path is `.maxbounty-capacity-controller.json` beside the existing lease. The small allowlist contains context/tab/session/frame identifiers, the authentication-attempt identity hash, an authenticated-evidence boolean, consumed authentication/pageView counters, blocked count and bounded request/response event-ID hashes. Binding metadata contains schema, owner-token hash, exact target-projection hash, source hashes and generation. No passwords, cookies, codes, request headers/bodies, auth response hashes, raw response text or rendered identity values are saved. The final tombstone has no campaign projection. State is fsynced/atomically replaced with mode 0600; nonregular, symlinked, hardlinked, oversized or group/world-readable checkpoint files refuse.

The existing private lease anchors the checkpoint's **exact producer-byte SHA-256 plus generation**, not a self-asserted checksum inside the checkpoint. Changing content, copying another owner's state, rolling back a prior checkpoint or changing request/source identity refuses. The digest is calculated from producer bytes, not a vulnerable post-write reread. The trust boundary is the protected lease, pinned code and cooperating local owner: this is **not** protection against an attacker who can rewrite both lease and controller or execute arbitrary same-user code. No signing secret or credential is introduced.

Before any stage browser I/O, the lease atomically changes to `in_progress`; only a normally completed pre-probe stage commits a new `ready` checkpoint. A crash, exception, swallowed producer refusal, overrun, uncheckpointable campaign attempt or uncertain browser effect leaves the stage non-resumable. Do not manually reset it or retry the effect. Resume never imports an arbitrary receipt. Expiry can permit a new lease owner but cannot adopt or replay the old controller. Owner/expiry are rechecked before each CDP call/event drain; escaped Python references are fenced when the lock scope exits. Browser-call completion after a timeout/expiry remains uncertain, never retried.

Request and response pauses have separate event identities. Their hashes and consumed budgets survive interpreter exit. Replayed IDs are refused before continuing or reading a response, including a replay of an already authenticated response. Authentication evidence additionally binds exact request ID, method, endpoint, context, target, session and main frame; mismatched responses cannot establish identity. The bounded ledger refuses rather than discarding old entries or resetting counters.
