## Verification contract and limits

`affiliate-program-status-readback-v1` is a normalized retained capture from an **authorized authenticated provider API adapter**, not a mailbox assertion. It must name exact network/program/name, cancelled/terminated relationship status, source notice event and timezone-aware observation, plus a matching captured `response.program_id` and `response.relationship_status`. Its file and original notice must exist under the custody root and match SHA-256. Hashes prove custody, not credentials: attaching this schema is a trusted-provider-reconciliation responsibility. There is no claim that every provider currently has an API that returns this status. Portal-only cases remain blocked until an independently reviewed equivalent adapter is available; no boolean email-only fallback.

Offline CI exercises the actual canonical inbox, sole writer and registry consumer with synthetic transports. Verbatim native selector excerpts produce a bounded six-surface exclusion candidate; this is **not** a full production-source HTML build. Candidate readback tests use explicitly synthetic HTML/JSON; native build failure is separately exercised. No mailbox, Sheet, live registry or release was changed.

Live acceptance remains open: one genuine event with raw/source/update IDs, authenticated provider capture, sole-writer row/value ACK, withdrawn registry/history readback, reviewed complete native site build, separately approved publication and canonical link/page-removal readback. Confirm replay produces no duplicate effect and do not follow affiliate links. Runtime adoption/enablement and independent safety review are separate from this PR.
