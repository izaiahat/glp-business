# Hermes workspace rules

## Purpose and authority
GLP Clinic Scout is an independent comparison publisher. Work on its current authorized revenue priorities; do not reopen another venture or a held workflow by inference. The operator's current instruction defines scope. Older reports and memories are evidence, not dispatch orders.

One coordinator owns priorities and assignments; each task has one end-to-end owner. Use the coordinator named in the live assignment, not a role inferred from a model, account, TUI name or quota reset. Workers never impersonate that role. Independent acceptance stays with its designated reviewer; outward-facing design retains independent Fable review.

## Work and proof
- Deliver small, reviewable changes: an isolated git branch/worktree, one PR, and CI tied to its exact head commit. Do not touch another owner's files or discard their work. Routine branch commits and PR submission must be within the assignment's authorization; merging and deploying are separate actions.
- Read the assigned outcome, relevant source and tests. Name task skills up front in every assignment; select them from `ops/linear/SKILL-INDEX.md` and load only those needed. Destination skills expose consolidated procedures in `references/MERGED-PROCEDURES.md`. Read the relevant current build-source entry before a build; do not load historical indexes wholesale.
- Fix the maintained source or registered producer, not its generated output. Reproduce defects when applicable, execute the actual checks, and report failures honestly. Tests prove tested behavior, not live business effects.
- Done means the requested outcome is verified. Link the commit/PR, real checks and any required runtime readback. If blocked, name the condition and owner; finish independent in-scope work. Do not invent filler, create another queue or endlessly retry.
- Preserve shared-resource locks, single-writer queues, cursors and idempotency. After an uncertain external action, inspect the exact target before retrying. Never kill an in-flight effect just to clear a slot.

## Non-negotiable boundaries
- Keep legal, privacy/PHI, identity/KYC, payment/spend, third-party-send and release approvals intact. An old approval covers only its exact scope. No paid fallback, access purchases or capacity-reset redemption by implication.
- Never expose, invent, create or reset credentials. Authorized account sign-ins use the AI browser and secure vault/MFA tools; a login form alone is not a blocker. Stop for an unsatisfied device challenge. Affiliate portals use authorized APIs first, otherwise a fresh browser run; no persistent portal profile. Playwright is for unauthenticated site tests.
- Keep Fella Health excluded and existing provider holds intact. Unknown is not zero. Substantiate health and commercial claims; do not imply we are a clinic. Do not follow affiliate tracking links merely to check them.
- Preserve the customized Hermes fork, other profiles, financial records and historical evidence. Only the designated parent updates shared STATE through its guarded writer.

## Coordination
Git/PR/CI carries implementation evidence. Linear is a small priority board, not a second build system: at most 20 open actionable issues including Triage and blockers. The coordinator loads `linear-orchestrator`; workers use the ten-line WORKER-STANDARD. Use OpenAI models for execution, explicit model/provider/effort, and host-wide admission: 4 total slots including external CLIs, depth 1, 2 writing PR lanes, 1 heavy build/browser. Leaf workers do not delegate. Compression uses Codex Sol; exhaustion means a deterministic checkpoint plus `/new`, never paid or Claude fallback. OpenRouter is removed. Runtime details: `~/.hermes/skills/linear-orchestrator/references/model-delegation-doctrine.md`.

STATE is a short handoff with timestamp, current owner, holds and next action; reconcile stale entries with current evidence. Report concise outcomes and blockers. Honor pauses. Use existing authorized communication routes: ops-alerts for status, payments for money/TEST cards, decisions for approvals; email is opt-in. Ask genuine unresolved questions together, without adding a new notification channel.

The host cron owns article publishing; the n8n article-carrier is inactive. Keep it inactive. D1–D7 authorize the rebuild, not unreviewed releases or sends; private repos are the source of truth, branch protection is deferred (do not claim it is enforced). Ideas belong in non-executable `ops/linear/BACKLOG.md`.
